# Local operations dashboard direction

The brief and existing private-admin visual language are binding. This is an
Operate-mode, code-led extension; it does not introduce a separate brand.

## THESIS

Evidence is the interface. The first screen tells the owner what is known, how old
it is, and what needs action before it offers detail.

## OWN-WORLD

The surface inherits MacServer's restrained blue-black operations world: fine rules,
quiet native typography, tabular measurements, mint only for verified health, amber
for attention, red for failure, and blue for a secondary data series. Depth belongs
only to the live plot; the remaining surface reads as one instrument board.

## STORY

Read top to bottom: overall evidence verdict and provenance; host vitals; time-series
rhythm plus recovery/network/request state; actionable alerts; then the service plane.
The footer restates the read-only, loopback-only trust boundary.

## FIRST VIEWPORT

At 1440x900 the owner sees the verdict, evidence age, host vitals, trend, active issue,
and beginning of the service plane without interaction. At 390px the same order stacks
without horizontal scrolling. Missing collector evidence says UNVERIFIED; stale evidence
says ATTENTION; a verified failure says ACTION REQUIRED.

## FORM

Impeccable direction seed `703d4977`, assigned index 7. The fixed repository brief and
incumbent admin system override an unrelated catalog world. Seven grounded candidates
were evaluated in the appliance context: server-room rack elevation, NOC incident wall,
flight-deck annunciator, electrical switchboard, oscilloscope bench, field-service log,
and a restrained host instrument board. The assigned seventh is the implemented form.
It uses a single evidence verdict, a ruled vitals strip, one plotted signal surface, an
incident timeline, and a service matrix. Motion is limited to data refresh; values remain
visible if the local API fails. No control, credential, fake metric, or decorative asset
appears.
